# Структура проекта

Описание модулей, функций, структур данных и их взаимосвязи.
Актуально на 2026-09-26.

## Карта файлов

```
src/
├── main.c        точка входа: связывает разбор аргументов и обработку файлов
├── args.h/.c     разбор командной строки, структура Options, открытие входа, справка
├── cat.h/.c      вывод содержимого с учётом флагов, структура CatState
└── my_errors.h   внутренние коды возврата
```

Направление зависимостей — только сверху вниз, циклов нет:

```
        main.c
       ↙      ↘
   args.h     cat.h
       ↘      ↙
      my_errors.h
```

`args.c` и `cat.c` друг о друге не знают. Это позволяет собирать тестовые
бинарники из любого подмножества объектников — см. `LIB_OBJS` в Makefile.

## Структура данных

### `struct Options` — [src/args.h](../src/args.h)

Результат разбора командной строки: что попросил пользователь.
Создаётся в `main`, заполняется в `ParseArgs`, дальше только читается —
поэтому в `FileProcessing` передаётся как `const struct Options *`.

| Поле | Тип | Смысл |
|------|-----|-------|
| `number_lines` | `bool` | флаг `-n` — нумеровать все строки |
| `number_nonblank` | `bool` | флаг `-b` — нумеровать только непустые |
| `squeeze_blank` | `bool` | флаг `-s` — схлопывать пустые строки |
| `show_ends` | `bool` | флаг `-E` — показывать `$` в конце строки |
| `show_tabs` | `bool` | флаг `-T` — показывать табуляцию как `^I` |
| `help` | `bool` | флаг `--help` |
| `file_count` | `int` | сколько имён лежит в `files` |
| `files` | `char **` | массив имён файлов в порядке из командной строки |

Про владение памятью:

- **массив `files`** выделяется в `ParseArgs` через `calloc` и принадлежит
  вызывающему — освобождать через `OptionsFree`;
- **сами строки** не копируются: это указатели внутрь `argv` либо на литерал
  `"-"`. Они живут всё время работы программы, освобождать их нельзя.

Структуру всегда создают нулевой (`struct Options opts = {0};`) — иначе в полях
окажется мусор со стека.

### `struct CatState` — [src/cat.h](../src/cat.h)

Состояние обработки: то, что меняется по ходу работы. Держится отдельно от
`Options` именно поэтому — `Options` только читается, `CatState` меняется.
Если слить их в одну структуру, у параметра `opts` пришлось бы убрать `const`,
и компилятор перестал бы подтверждать, что настройки не портятся.

| Поле | Тип | Смысл |
|------|-----|-------|
| `line_number` | `int` | сквозной счётчик строк для `-n` и `-b` |
| `at_line_start` | `bool` | следующий символ начинает новую строку |
| `prev_blank` | `bool` | предыдущая строка была пустой — для `-s` |

Создаётся **один раз** в `main`, до обхода файлов: `{1, true, false}`.
Все три поля обязаны пережить вызов `FileProcessing`, потому что нумерация
и позиция в строке сквозные через файлы. Проверено на эталоне: если файл
не заканчивается переводом строки, следующий продолжает ту же строку
и номера не получает.

## Коды возврата — [src/my_errors.h](../src/my_errors.h)

| Константа | Значение | Когда |
|-----------|----------|-------|
| `SUCCESS` | 0 | ошибок нет |
| `MEMMORY_ERROR` | 1 | `calloc` в `ParseArgs` вернул `NULL` |
| `UNKNOWN_FLAG_ERROR` | 2 | в аргументах встретился неизвестный флаг |
| `INPUT_ERROR` | 3 | не удалось открыть файл |
| `HELP_REQUESTED` | 4 | **не ошибка**: запрошена справка, разбор прекращён |
| `OUTPUT_ERROR` | 5 | не удалось записать в выходной поток |

Это **внутренние** коды, наружу они не выходят: `main` возвращает 0 при успехе
и 1 при любой ошибке, как настоящий `cat`. `HELP_REQUESTED` тоже превращается
в 0 — справка не сбой.

## Функции

### `int ParseArgs(int argc, char *argv[], struct Options *opts)`

[src/args.c](../src/args.c) — разбирает командную строку и заполняет `opts`.

Выделяет массив на `argc` элементов — заведомо с запасом, имён файлов не может
быть больше, чем всего аргументов. Затем идёт по `argv`, начиная с первого:

| Вид аргумента | Что делает |
|---------------|------------|
| начинается с `-`, длиннее одного символа | передаёт в `ParseFlags` |
| всё остальное, включая ровно `-` | добавляет в список файлов |

Если файлов не нашлось, подставляет `"-"` — тогда всё остальное может работать
единообразно, не зная, читаем мы файл или stdin.

Возвращает `SUCCESS` либо код от `ParseFlags`. Разбор прерывается на первом же
ненулевом коде, поэтому `cat --help -z` печатает справку, а `cat -z --help` —
ошибку: как у GNU, кто первый, тот и прав. При ненулевом коде содержимое
`files` не определено.

После вызова обязателен `OptionsFree` — в том числе при ошибке, память могла
уже выделиться.

### `int ParseFlags(const char *arg, struct Options *opts)`

Разбирает одну группу флагов. Выделена из `ParseArgs`, когда та переросла
42 строки; заодно упала вложенность с четырёх уровней до двух.

Сначала целиком сравнивает аргумент с `--help` — одним `strcmp`, а не на каждом
символе. Затем: аргумент начинается с `--` → неизвестный длинный флаг; иначе
идёт посимвольно, так работают склейки вида `-nE`.

Возвращает `SUCCESS`, `HELP_REQUESTED` или `UNKNOWN_FLAG_ERROR`. Флаги,
разобранные до ошибки, остаются взведёнными: `-n2` успевает включить `-n`.
Сообщение об ошибке печатает сама, дословно как GNU `cat`:

```
cat: invalid option -- 'z'
cat: unrecognized option '--number'
Try 'cat --help' for more information.
```

### `int PrintHelp(FILE *out)`

Печатает справку. Перечислены только реализованные флаги, поэтому текст
не совпадает со справкой GNU — и в `run.sh` не сравнивается.

Возвращает `OUTPUT_ERROR`, если запись не удалась. Проверяется `fflush`, а не
результат `fputs`: вывод буферизован, и сбой проявляется только при сбросе.

### `void OptionsFree(struct Options *opts)`

Освобождает массив `files`, обнуляет указатель и `file_count`. Оставляет
структуру в согласованном состоянии: обход по `file_count` после вызова просто
не выполнится. Вызывать повторно безопасно.

### `FILE *OpenInput(const char *path_to_file)`

Возвращает `stdin` для имени `"-"`, иначе открывает файл на чтение.
При неудаче — `NULL` (причина в `errno`).

Смысл функции в том, чтобы вызывающий не различал stdin и файл.

Отдельно обрабатывается каталог: `fopen` на нём **успешно** возвращает поток,
и только первое чтение падает. Без проверки каталог выглядел бы как пустой файл.
Поэтому сразу после открытия делается `fstat` + `S_ISDIR`, и при совпадении
функция закрывает поток, ставит `errno = EISDIR` и возвращает `NULL` — дальше
`main` печатает обычное `Is a directory`.

### `void CloseInput(FILE *in)`

Парная к `OpenInput`. Обычный файл закрывает, а `stdin` — **не закрывает**,
вместо этого сбрасывает у него признак EOF через `clearerr`.

Закрывать `stdin` нельзя: он один на всю программу, и `cat a.txt - b.txt -`
обратится к нему дважды. А `clearerr` нужен потому, что stdio запоминает
достигнутый конец файла и все последующие чтения возвращали бы EOF сразу.
Для терминала это неверно: Ctrl+D завершает только текущее чтение, после него
можно вводить дальше.

### `int FileProcessing(FILE *in, FILE *out, const struct Options *opts, struct CatState *state)`

[src/cat.c](../src/cat.c) — копирует байты из `in` в `out`, применяя флаги.

Принимает `out` параметром, а не пишет в `stdout` напрямую: иначе функцию
нельзя было бы проверить в тесте, подсунув ей буфер вместо экрана.

Чтение побайтовое. Цикл — четыре строки, по одной заботе в каждой:

```c
while ((ch = fgetc(in)) != EOF) {
    if (!SkipBlankLine(opts, state, ch)) {
        PrintLineNumber(out, opts, state, ch);
        PrintChar(out, opts, ch);
    }

    state->at_line_start = (ch == '\n');
}
```

Последняя строка стоит вне всяких проверок флагов: позиция в строке — свойство
данных, а не опций. Пока она была внутри проверки `-n`, флаги `-s` и `-b`
работали бы только вместе с ним.

После цикла — `fflush` и `ferror`: одна проверка записи на весь файл вместо
проверки каждого `fputc`. Сообщение печатает вызывающий, потому что `main`
уже владеет форматом сообщений, а `errno` к тому моменту ещё не затёрт.

Помощники объявлены `static`, снаружи не видны и проверяются через саму
`FileProcessing`:

| Функция | Роль |
|---------|------|
| `NeedLineNumber(opts, ch)` | **только отвечает** нужен ли номер. Двух параметров достаточно, менять состояние нечем — это гарантия, заданная сигнатурой. Здесь же правило «`-b` перекрывает `-n`» |
| `PrintLineNumber(out, opts, state, ch)` | печатает префикс и сдвигает счётчик. Инкремент внутри того же `if`, что и печать, — поэтому `-b` не тратит номера на пустые строки |
| `SkipBlankLine(opts, state, ch)` | `-s`: решение по первому символу строки, здесь же обновляется `prev_blank` |
| `PrintChar(out, opts, ch)` | `-E` и `-T`: как записать входной символ |

Разбиение не случайное: флаги вмешиваются тремя разными способами — добавляют
вывод перед символом (`-n`, `-b`), меняют вид самого символа (`-E`, `-T`),
выбрасывают строку целиком (`-s`). Поэтому единой формы «функция на флаг» нет:
у `-s` предикат, у остальных — процедуры.

Табуляцию в префиксе номера `-T` не трогает: префикс печатается через `fprintf`,
минуя `PrintChar`. Проверено на эталоне — `cat -nT` оставляет её настоящей.

### `int main(int argc, char *argv[])`

[src/main.c](../src/main.c) — только склейка, вся логика в модулях:

```
Options opts = {0}
CatState state = {1, true, false}
flag_err = ParseArgs(argc, argv, &opts)

если flag_err == HELP_REQUESTED  → PrintHelp(stdout)
иначе если flag_err == SUCCESS   → для каждого имени в opts.files:
                                       in = OpenInput(имя)
                                       если NULL → сообщение в stderr, запомнить ошибку
                                       иначе     → FileProcessing(...), при сбое записи
                                                   сообщение и выход из цикла
                                                   CloseInput(in)
OptionsFree(&opts)
return ошибка ? 1 : 0
```

Ошибка открытия одного файла не прерывает обход — остальные выводятся, как
у `cat`. А ошибка **записи** прерывает: писать всё равно некуда, и сообщение
должно быть одно, сколько бы файлов ни осталось.

Держать в `main` только это — сознательное решение: тестовый бинарник приносит
свой `main`, поэтому всё, что нужно проверять, должно лежать в других файлах.
В Makefile это видно как `LIB_OBJS = $(filter-out $(BUILD)/main.o,$(OBJS))`.

## Поток выполнения

```
argv ──► ParseArgs ──► ParseFlags ──► struct Options ──┬──► флаги ──┐
                                                       │            │
                                                       └─► files[] ─┼─► OpenInput ─► FILE*
                                                                    │        │
                                              CatState ─────────────┴────────┤
                                                                             ▼
                                                                      FileProcessing ──► stdout
                                                                             │
                                                                             ▼
                                                                        CloseInput
```

## Что ещё не сделано

Все обязательные требования плана выполнены. Остаются мелочи:

- Имя программы в сообщениях зашито как `cat`, а GNU берёт его из `argv[0]`.
  Из-за этого `run.sh` приходится приводить префиксы к общему виду через `sed`.
- Опечатка в имени `MEMMORY_ERROR` — лишняя `m`.
- Неудачный `calloc` в `ParseArgs` ничем не воспроизвести, так что путь
  `MEMMORY_ERROR` не проверен ни одним тестом.
