# Тесты из `tests/test_cat.c`

Всего 20 тестов, все проходят (проверено 26.09.2026). Запуск: `make test`

Как устроено тестирование в целом — [README.md](README.md).

Проверяемая функция одна — `FileProcessing` из [src/cat.h](../src/cat.h). Помощники
`NeedLineNumber`, `PrintLineNumber`, `SkipBlankLine`, `PrintChar` объявлены `static`
в `cat.c` и снаружи не видны: они проверяются через неё.

Каждый тест устроен одинаково: строка на входе, строка на выходе, флаги в `Options`,
начальное состояние в `CatState`. Механику берёт на себя помощник:

```c
static int RunFileProcessing(char *input, const struct Options *opts, struct CatState *state,
                             char *out_buf, size_t size);
```

Он открывает вход через `fmemopen`, выход через `tmpfile`, вызывает `FileProcessing`
и читает результат обратно в буфер. Возвращает код `FileProcessing`, поэтому проверка
`mu_assert_inteq(0, RunFileProcessing(...))` заодно подтверждает, что запись прошла.

Состояние задаёт сам тест и может проверить его **после** вызова — это то, чего
не видит `run.sh`: он сравнивает только вывод, поля структуры ему недоступны.

## 1. Без флагов

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_copies_input` | `abc` | `abc` |
| `test_copies_empty_input` | пусто | пусто |
| `test_copies_multiline` | `a\nb\n` | `a\nb\n` |
| `test_copies_utf8` | `лол\n` | `лол\n` |

Пустой вход — единственный случай, когда цикл в `FileProcessing` не выполняется
ни разу. UTF-8 проверяет, что побайтовое копирование не портит многобайтовые символы.

## 2. `-n` — нумерация всех строк

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_number_lines` | `a\nb\n` | `␣␣␣␣␣1\ta\n␣␣␣␣␣2\tb\n` |
| `test_number_counts_blank` | `a\n\nb\n` | номера 1, 2, 3 — пустая строка тоже нумеруется |
| `test_number_no_trailing_newline` | `a\nb` | `␣␣␣␣␣1\ta\n␣␣␣␣␣2\tb` |

Формат префикса — шесть позиций под число с выравниванием вправо и табуляция,
как у GNU `cat`.

## 3. `-b` — нумерация непустых строк

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_number_nonblank_skips_blank` | `a\n\nb\n` | `1 a`, пустая без номера, `2 b` |
| `test_number_nonblank_overrides` | то же, но взведены и `-n`, и `-b` | результат как у `-b` |

Второй тест закрепляет правило из требований: `-b` перекрывает `-n`. Обрати внимание,
что пустая строка не только остаётся без номера, но и **не тратит** номер — следующая
получает 2, а не 3.

## 4. `-s` — схлопывание пустых строк

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_squeeze_collapses` | `a\n\n\n\nb\n` | `a\n\nb\n` |
| `test_squeeze_keeps_single` | `a\n\nb\n` | без изменений: одиночная пустая уцелела |
| `test_squeeze_leading_blanks` | `\n\n\na\n` | `\na\n` |

Третий случай отдельный: пустые строки в начале файла, когда «предыдущей строки»
ещё не было.

## 5. `-E` и `-T` — как выводится символ

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_show_ends` | `a\nb\n` | `a$\nb$\n` |
| `test_show_ends_no_trailing_newline` | `a\nb` | `a$\nb` — без `\n` нет и `$` |
| `test_show_tabs` | `a\tb\n` | `a^Ib\n` |
| `test_number_tab_not_converted` | `a\tb\n` с `-nT` | `␣␣␣␣␣1\ta^Ib\n` |

Последний — самый полезный в разделе. `-T` действует только на **входные** символы:
табуляция, которую печатает сам префикс номера, остаётся настоящей. Проверено на GNU `cat`.

## 6. Комбинация

| Тест | Вход | Ожидается |
|------|------|-----------|
| `test_all_flags_together` | `a\tb\n\n` с `-nET` | `␣␣␣␣␣1\ta^Ib$\n␣␣␣␣␣2\t$\n` |

Проверяет порядок: номер идёт первым, `^I` вместо таба, `$` перед переводом строки.

## 7. Состояние между вызовами

| Тест | Что проверяет |
|------|---------------|
| `test_number_updates_state` | после двух строк `state.line_number` равен 3 |
| `test_number_continues_across_calls` | два вызова с одним `state`: номера 1 и 2, счёт не начинается заново |
| `test_unfinished_line_continues` | первый вызов получает `x` без `\n`, второй — `y\nz\n`; вывод `␣␣␣␣␣1\tx` и `y\n␣␣␣␣␣2\tz\n` |

Эти три — главная причина, по которой юнит-тесты нужны вдобавок к `run.sh`.
Третий воспроизводит поведение, снятое с эталона: если файл не заканчивается
переводом строки, следующий файл продолжает ту же строку и номера не получает.
Отсюда `at_line_start` живёт в `CatState`, а не в локальной переменной.

## Чего пока нет

- Ошибка записи: `FileProcessing` возвращает `OUTPUT_ERROR`, если сброс буфера не удался,
  но тестом это не покрыто — нужен поток, отказывающийся принимать данные.
  Ручная проверка: `./build/cat tests/data/simple.txt > /dev/full`.
- Данные с нулевыми байтами: помощник сравнивает результат как строку через `strcmp`,
  поэтому `\0` внутри не проверить. Понадобится — сравнивать через `memcmp` с длиной.
- Вход длиннее буфера в 256 байт: помощник обрежет результат молча.
